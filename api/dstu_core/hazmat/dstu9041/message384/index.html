Message formatting for DSTU 9041’s l(p)=384 case (T-297 - clauses 5.7/5.8/Table 1, 11 steps 2-8, 12 steps 9-18, the clause set message.rs/message512.rs cite). A third sibling, generated from message512.rs by script.

Byte layout for l(p)=384 (Table 1’s row: l_max(p)=296, l_H=64 bits): M~ is 37 bytes, left-padded with zeros; l_M~ is the 2-byte big-endian bit length (clause 5.2); M' is i_H(1) || H(l_M~||M~) truncated to l_H=64 bits, LOW-order end (8) || l_M~(2) || M~(37) = 48 bytes - not a multiple of Kalyna-256’s 32-byte block, so encryption384 wraps M' itself with KW-p (DSTU 7624 §15.4), not M' || 0^l with KW as 256/512 do. Додаток Г.2’s printed H and M' match this layout exactly; its t does not follow §15.4 (D-241).
