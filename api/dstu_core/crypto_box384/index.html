crypto_box equivalent at l(p)=384 (E384/1, docs/TASKS.md T-297, docs/DECISIONS.md D-245) - a sibling of crate::crypto_box (256) and crate::crypto_box512 (512) at this curve size’s widths, generated from crypto_box512.rs (owner: sibling modules, D-241).

§Seed width - 32 bytes, as crypto_box512 (D-182)

l(p)=384’s L_MAX_P is 296 bits (37 bytes), more than the 32-byte seed the stream-key derivation takes, so the seed is wrapped at message_bits = 256 and open requires exactly that bit length back - hazmat::dstu9041::encryption384::decrypt returns the encryptor’s authenticated l(M) field, checked in message384::parse_m_prime (read, not assumed).

§PublicKey is 48 bytes - the curve point’s x-coordinate only

The compression argument is a curve-family property (-(x,y) = (x,-y) in this standard’s swapped-Edwards form, so x_{k*Q} = x_{k*(-Q)} and kappa does not depend on which square root crate::hazmat::dstu9041::curve384::point_from_x returns); it holds for E384/1 as for E256/1 and E512/1. kappa here is the low 256 bits of that x (D-244), which changes nothing in the argument. PublicKey::from_bytes reuses point_from_x’s rejection gauntlet.

§Error collapsing, wire format

As crate::crypto_box512: OpenError does not tell a KEM failure from a stream failure; only OpenError::Truncated and OpenError::UnsupportedVersion stay separate. Wire format version 3 only (D-239): version (1, = 3) || dstu9041_ciphertext (176) || <D-208 stream file>, through seal_stream/open_stream or seal/open. There is no version 2 at this size: nothing was ever sealed with it. Stream key: Kupyna256Kmac(key = seed, message = b"cryptbx3" || version || kem_ciphertext || recipient_public_key) (D-201’s binding, its own label).

A blob for another curve size fails as InvalidCiphertext or Truncated, the same posture as between crypto_box and crypto_box512.

§Provenance

Not DSTU-specified - no vector oracle exists for this composite; verified by property, tamper and misuse tests (tests/crypto_box384.rs). hazmat::dstu9041::encryption384 is checked against Додаток Г.2 as far as the document follows DSTU 7624 (D-241).

Functions§

open
Decrypts sealed (as produced by seal or seal_stream) under secret - the in-memory form of open_stream. Partially decrypted plaintext is zeroized before an error returns.
open_stream
Starts opening a message sealed by seal or seal_stream (T-265): prefix is its first OPEN_STREAM_PREFIX_BYTES bytes. Feed the returned FileDecryptor everything after them, as the stream-file codec documents: a record’s plaintext comes out only once it verifies, the Final record’s only from finish, once the input is known to end there.
seal
Encrypts message (any length) to recipient, drawing a fresh random seed and ephemeral key internally - see the module doc’s “Seed width” section. The in-memory form of seal_stream; the result is sealed_len(message.len()) bytes.
seal_stream
Starts sealing a message of any length to recipient as a stream (T-265): returns the FileEncryptor for its records and the SEAL_STREAM_PREFIX_BYTES-byte prefix to write first. Drive the encryptor as the stream-file codec documents (every full CHUNK_BYTES chunk with seal_chunk, the last 0..=CHUNK_BYTES bytes with seal_final); the bytes are then exactly what seal returns, and open/open_stream read them. The stream key never leaves the library.
sealed_len
The exact length seal returns for a message_len-byte message, or None if it overflows usize: the prefix, the message, and one record overhead per started CHUNK_BYTES chunk - at least one, since an empty message is one empty Final record.
